# شیفت‌یار — نسخهٔ اولیهٔ سامانهٔ برنامه‌ریزی شیفت

Next.js 16 + TypeScript + Tailwind CSS 4 + PostgreSQL. رابط کاربری فارسی، راست‌به‌چپ و با فونت Yekan است. هر سازمان محیط کار جداگانه دارد؛ داده‌ها در درخواست‌ها با شناسهٔ سازمان محدود می‌شوند. ساخت محیط کار فقط در پنل مدیر ارشد انجام می‌شود.

## راه‌اندازی مدیر ارشد و دسترسی سازمانی

پس از اجرای مهاجرت‌های پایگاه داده با `npm run db:migrate`، یک مدیر ارشد اولیه بسازید. مقادیر زیر را فقط برای اجرای فرمان در محیط تنظیم کنید؛ رمز را در مخزن یا فایل تنظیمات نسخه‌بندی‌شده نگه ندارید:

```powershell
$env:SUPERADMIN_NAME = "مدیر سامانه"
$env:SUPERADMIN_EMAIL = "admin@example.com"
$env:SUPERADMIN_PASSWORD = "<یک رمز اختصاصی با دست‌کم ۱۲ نویسه>"
npm run admin:create
Remove-Item Env:SUPERADMIN_PASSWORD
```

مدیر ارشد از `/admin/login` وارد پنل `/admin` می‌شود. در پنل، فهرست سازمان‌ها را می‌بیند و سازمان، منطقهٔ زمانی، نام و ایمیل نماینده و رمز موقت او را ثبت می‌کند. محیط کار و حساب نماینده در یک تراکنش ساخته می‌شوند. برای سازمان موجود نیز می‌توان نمایندهٔ جدید افزود. رمز موقت را مدیر ارشد از راهی امن در اختیار نماینده می‌گذارد؛ سامانه در این نسخه ایمیل دعوت ارسال نمی‌کند. نماینده از `/login` وارد می‌شود و پیش از دسترسی به داشبورد و خروجی، باید رمز موقت را تغییر دهد. مسیر `/signup` فقط نحوهٔ دریافت دسترسی را توضیح می‌دهد و ثبت‌نام عمومی ندارد.

در فهرست سازمان‌ها، «مشاهده و مدیریت» جزئیات هر سازمان، حساب‌های نمایندگان و آمار برنامه‌ها را نشان می‌دهد. مدیر ارشد می‌تواند نام و منطقهٔ زمانی را ویرایش کند، سازمان را غیرفعال یا دوباره فعال کند و پس از غیرفعال‌سازی، با وارد کردن نام دقیق سازمان آن را دائماً حذف کند. غیرفعال‌سازی نشست‌های نمایندگان را پایان می‌دهد و ورود، داشبورد، خروجی و ساخت برنامه را می‌بندد. فعال‌سازی دوباره نیازمند ورود مجدد نمایندگان است. حذف دائمی همهٔ داده‌های همان سازمان، از جمله برنامه‌های ذخیره‌شده را پاک می‌کند. این امکانات به مهاجرت `db/004_organization_status.sql` نیاز دارند؛ `npm run db:migrate` مهاجرت‌های موجود را به‌ترتیب اجرا می‌کند.

## راه‌اندازی

1. PostgreSQL را اجرا کنید و یک پایگاه دادهٔ خالی به نام `shiftwise` بسازید.
2. اگر `.env.local` وجود ندارد، `cp .env.example .env.local` را اجرا کنید و سپس `DATABASE_URL` و `SESSION_SECRET` را تنظیم کنید. کلید نشست باید تصادفی و دست‌کم ۳۲ نویسه باشد.
3. در پوشهٔ `shiftwise` فرمان‌های زیر را اجرا کنید:

```bash
npm install
python -m pip install -r requirements.txt
npm run db:migrate
npm run dev
```

برای حل پیش‌فرض با CP-SAT به Python 3 و بستهٔ OR-Tools نیاز است. در صورت نیاز، مسیر مفسر Python را با متغیر محیطی `SHIFTWISE_PYTHON` مشخص کنید. حل‌گر ابتدا تعداد جایگاه‌های پوشش‌داده‌شده را بیشینه می‌کند و سپس، اگر بهینگی پوشش ثابت شده باشد، ساعت کارکنان را متعادل می‌کند. اگر زمان حل پایان یابد، بهترین جواب مجاز پیدا شده بازگردانده می‌شود؛ در صورت نبود جواب، خطا گزارش می‌شود.

برنامه روی `http://localhost:3000` اجرا می‌شود. پس از ساخت محیط کار توسط مدیر ارشد، نماینده وارد می‌شود، نقش‌ها، کارکنان، الگوهای شیفت، نیاز هفتگی و مرخصی را ثبت می‌کند و برنامهٔ یک هفته را می‌سازد. خروجی CSV از برنامهٔ ذخیره‌شده قابل دریافت است.

## دادهٔ نمایشی کارخانه

پس از ایجاد سازمان و حساب نماینده، داده‌های مصنوعی را در همان سازمان وارد کنید:

```bash
npm run seed:demo -- --organization "کارخانه نمونه"
npm run seed:verify -- "کارخانه نمونه"
```

اگر چند سازمان هم‌نام وجود دارد، برای seed از `--org-id <شناسهٔ سازمان>` استفاده کنید. seed شامل ۳ نقش (اپراتور تولید، تکنسین نگهداری، سرپرست شیفت)، ۲۴ کارمند ساختگی، شیفت‌های صبح، عصر و شب و ۶۳ قانون نیاز پوشش برای هفت روز هفته است. در مجموع هر هفته ۷۷ جایگاه کاری دارد. اجرای دوباره، دادهٔ تکراری ایجاد نمی‌کند و مقادیر موجود را بازنویسی نمی‌کند؛ اگر نام کارمند یا ساعت شیفت با دادهٔ موجود تعارض داشته باشد، تراکنش بدون تغییر برمی‌گردد. رمز و حساب کاربری به‌عنوان دادهٔ نمونه ساخته نمی‌شود. فرمان دوم برنامه‌پذیری هفتهٔ شنبهٔ پیش رو را با CP-SAT به‌صورت خواندنی می‌سنجد و برنامه‌ای در پایگاه داده ذخیره نمی‌کند. برای نمایش خروجی، نماینده وارد داشبورد می‌شود و دکمهٔ «ساخت برنامه» را برای هفتهٔ دلخواه می‌زند.

## مدل و مرزهای نسخهٔ اولیه

- هر قانون پوشش، تعداد کارکنان موردنیاز یک نقش در یک شیفت و روز هفته را تعیین می‌کند. شیفت‌ها می‌توانند از نیمه‌شب عبور کنند.
- برنامه‌ریز مهارت، مرخصی، تداخل زمانی، حداقل فاصلهٔ استراحت، حداکثر ساعت هفتگی، روزهای کاری پیاپی و سقف شیفت شب را بررسی می‌کند. هفته از شنبه آغاز می‌شود. الگوریتم پیش‌فرض CP-SAT این محدودیت‌ها را به‌صورت قیود سخت اعمال می‌کند؛ اول پوشش جایگاه‌ها و سپس توازن ساعت کاری را بهینه می‌کند. جایگاه‌های بدون نیرو در گزارش ثبت می‌شوند. اثبات بهینگی تنها هنگامی معتبر است که حل‌گر وضعیت بهینه برگرداند؛ با پایان مهلت ممکن است خروجی صرفاً بهترین جواب یافت‌شده باشد.
- قوانین فقط **در هفتهٔ انتخاب‌شده** بررسی می‌شوند؛ استراحت و روزهای پیاپی در مرز میان دو هفته در این نسخه کنترل نمی‌شوند. ساعت شیفت شبانه به روز آغاز آن نسبت داده می‌شود. این برنامه محاسبه‌گر حقوق یا ابزار تضمین انطباق قانونی نیست.
- برنامه‌های خروجی پیش‌نویس هستند. پس از تغییر داده یا قوانین، برنامهٔ ذخیره‌شده خودکار به‌روز نمی‌شود؛ دوباره تولید و بازبینی کنید.
- ورود سازمانی با رمز عبور و کوکی نشست انجام می‌شود. برای عرضهٔ عمومی هنوز بازیابی رمز، تأیید ایمیل، محدودسازی درخواست‌های ورود، دعوت همکاران، ثبت رخدادها، نظارت، پشتیبان‌گیری و کنترل نقش‌های مدیریتی لازم است.
- پیاده‌سازی COOP1 همچنان برای مقایسهٔ پژوهشی در `lib/coop1.ts` موجود است. آن را معادل نتایج آزمایش‌های مقاله تلقی نکنید؛ برای ادعای پژوهشی باید مقایسهٔ مستقل انجام شود. کد اصلی دانشگاهی در پوشهٔ دیگر دست‌نخورده است.

فونت `public/fonts/Yekan.woff2` همراه مجوز OFL در `public/fonts/LICENSE.txt` نگهداری می‌شود.
